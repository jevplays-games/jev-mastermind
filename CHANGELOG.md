# Changelog

## Unreleased

Matches stored before the rename (`game:"mastermind"`) can finish again. The end-of-match check compared each stored match with one rebuilt from its replay, which is always `typecrack`. Every final opponent move, resignation and expiry of such a match therefore failed with HTTP 500 and left it stuck as active. The check now accepts the stored legacy id. `tests/fixtures/legacy-mastermind-matches.json` holds real in-progress rows written by the pre-rename server, and tests finish, resign and expire them. The Node server (`server/dev.mjs`) now serves `LEGACY_ORIGINS` hosts like the Worker, with the same D9 parsing.

Display fixes:
- Keycap letters on the opponent board are no longer faded below 4.5:1 on phones.
- An imported replay that ended before the opponent moved reads "No opponent moves, not Jev".
- Before the script runs, the page names the opponent neutrally.
- The header title stays whole at 600–639px.
- On short phones the ten board rows clear the sticky composer.

Final review fixes (issues #13 and #14). Local practice is never presented as Jev: the match-analytics outcome card printed the raw difficulty key and finish reason, so a match against the local solver read "jev · normal"; it now names who played, from the replay's own opponent moves (for example "Local solver, not Jev · Jev difficulty · Completed"), and the record tables show the difficulty menus' tier names and readable results instead of `jev` and `jev_break` (`public/labels.js`, `tests/opponent-labels.test.mjs`). The hardest tier keeps its menu name, Jev, and appears only as a difficulty, never as the opponent; whether to rename that tier is an open owner decision. New tests check that every export of a local match presents the local solver and never Jev: for a local-opponent server match the replay, the full analytics JSON, the moves and decisions CSVs, the server analytics and the retained record, and in the browser suite the same downloads from a finished browser-practice match. Stored keys, exports and cohorts are unchanged. The setup heading and the opponent's board monogram follow the actual opponent. Layout: the result plaque no longer squeezes its text to one word per line beside its buttons, and its text is ink (the muted subtitle was 3.7:1 on the magenta win plaque); the three-column layout fits 1024px instead of scrolling sideways, keeps both boards the same width with every row aligned, and leaves a gap above the evidence panel; the board column header no longer runs "GUESS" into "CODE"; empty guess slots are filled wells; on phones the setup panel leads after New match and the header keeps the game title whole beside the provenance badge. The README banner's CHOICE window now selects the guess being typed (AEBF) and its alt text describes the canonical robot. The browser suite follows the auto-start flow and passes again. A second pass: from 601 to 859px the stacked board panels keep the 24px panel gap (they touched the result plaque, the composer and the evidence panel); the three-column layout starts at 940px, where its columns fit, and the stacked layout covers 860 to 939px at heights up to 950px (there the three columns pushed the controls past the right edge, where they were cut off, or wrapped the last key onto its own row); the secret palette keeps all six keys on one row from 900 to 939px; the jevplay.games wordmark shows in the header from 1400px (it was hidden up to 1499px); keyboard focus and anchor targets stop below the sticky header instead of under it; and while a guess is being typed, Enter on a link or on the rules summary keeps its own meaning, so the skip link, "How to play" and the rules work from the keyboard during a match. Screenshots retaken; static size remeasured.

New pink/ink pixel art (issue #14). The six code symbols A–F are now square pixel keycaps with the letter drawn in the art. Each fill differs in lightness or pattern (pink, ink, paper, blue, pink with dots, grey with hatching), so colour is never the only cue. Blue on D is the only accent colour, and it stays out of the mark, icons, badges and banners, and every letter reaches at least 4.5:1 against its keycap. The hidden code is a padlocked grey keycap. Exact and near feedback are a filled and a hollow ink square. The art replaces the earlier round glossy pegs and black and white key pegs. The app mark, favicon, apple-touch icon and win/draw/loss badges are redrawn as well. The README banner is now `assets/banner.png` (2560×840, replacing `assets/banner.jpg`); `public/brand/og.png` and a new `assets/social-preview.png` are rendered from HTML sources in `assets/src/`. The overlay letter on symbol keycaps is now hidden visually but kept for screen readers. Entropy-chart axis labels are larger below 600px. The screenshots in `reports/screenshots/` were retaken from a real local run.

Renamed Mastermind to **Typecrack** under the jevplay.games brand (issue #13). Display name, page title and meta, header wordmark (`jevplay.games`), footer, Discord command text and launch button, export filenames (`typecrack-*`), package and Worker name (`jev-typecrack`), canonical origin (`https://typecrack.jevplay.games`) and the shared module directory (`public/typecrack/`) change. The opponent is written Jev. Theme moves to the shared pink/ink pixel-window brand with the default ink accent; peg art is unchanged pending the art issue. The D1 database keeps its existing name `mastermind`.

Compatibility: new state and replays carry `game:"typecrack"`; stored state, exported replays, match creation and Discord `/play` still accept `mastermind`. New matches commit secrets under `jev-typecrack-commit-v2`; verification also accepts `jev-mastermind-commit-v1`, so every earlier commitment and replay still verifies (`tests/rename-compat.test.mjs`). `/play/mastermind` answers 301 to `/play/typecrack` with its query. `mastermind.jevplay.games` stays routed and is served on its own origin through the new `LEGACY_ORIGINS` setting until cutover. The Node server keeps using an existing `mastermind.sqlite`.

Prompt version bumped to `mm-prompt-v2`: the provider instructions now name Typecrack and the request carries `game:"typecrack"`. Rules (`mm-4x6-10-v1`), policy (`mm-policy-v1`) and analytics (`mm-analytics-v1`) behaviour is unchanged, so those labels are not changed. Because the opponent configuration hash includes the prompt version, every new match, local-opponent ones included, gets a new `configId` cohort (local opponent `mm-118f378e1c8d3f67abd3d254` → `mm-f93deb5ecdf108bf4d6fb8bd`; Jev `mm-9e42af838644c074c3cf8938` → `mm-f576f9cb98a973f69b670fc8`); v1 cohorts stay separate and are not relabelled. **Visible effect:** leaderboards and community analytics default to the current `configId`, so pre-rename matches drop out of those default views. They are still stored and still reachable with `?configId=<old id>`, and the personal record still lists them as their own configuration groups. Ranked play is off, so no live standings move. The benchmark was regenerated for the moved and edited source files.

Discord Activity mode: bearer-token sessions, an `/api/activity/*` sign-in exchange and frame_id-gated framing headers, described in `docs/ACTIVITY.md`. Game rules, policy, prompt and model behavior are unchanged, so no version was bumped.

Default match difficulty is now `jev` (minimax-filtered) instead of `normal`; a difficulty the player has already chosen is still restored from local storage. Leaderboard and analytics filters are unchanged, and browser practice remains an explicitly local, unranked solver.

Response validation now derives the probability-sum tolerance from the provider's 0.01 reporting grain. The previous fixed 0.001 window rejected every real response, so live JEV decisions silently fell back; the test fixtures returned exact one-hot distributions and could not catch it.

## 1.0.0 — 2026-09-22

Implemented the two-leg game, four structured policies, live TypeSafe adapter, explicit practice/fallback modes, authoritative match API and replay commitments, Discord identity/launch flows, D1 schema and local SQLite adapter, cohort leaderboards, record/operational analytics, exhaustive all-alternative analysis and exports, tests, baseline harness and deployment documentation.

Packaged results distinguish executed native/exhaustive/offline-DOM checks from unperformed credentialed integrations and conventional browser-origin tests. No production deployment is implied.
